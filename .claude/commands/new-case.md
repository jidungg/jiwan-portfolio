새 문제 해결 사례를 작성한다. 주제: $ARGUMENTS

## 절차

1. **소스 확인** — `Sources/` 안의 관련 자료를 찾는다. 사용자가 GitHub·Notion 등 외부 소스를
   언급하면 그것도 확인한다. 이 시점에 관련 자료를 못 찾으면 사용자에게 어디서 정보를
   가져와야 하는지 먼저 묻는다.

2. **질문으로 캐낸다** — 다음이 채워지기 전까지 초안을 쓰지 않는다.
   - 상황·제약 (왜 문제였고, 무엇이 어려웠는가)
   - **접근** — 검토했다가 버린 대안 최소 1개와 버린 이유. 이게 제일 중요하다.
     사용자가 "그냥 이렇게 했어요"라고만 답하면, "그 방법 말고 처음에 고려했다가
     안 쓴 방법 없었어요?"라고 다시 물어라.
   - 구현 핵심 (코드 20줄 이내로 압축 가능한 정도)
   - 결과 — 숫자와 측정 조건 (기기, 씬, 반복 횟수 등)
   - 회고 — 지금 다시 하면 무엇을 바꿀 것인가

3. **id/slug을 정한다** — 영문 kebab-case. `Cases/<slug>.md`가 파일명이 된다.

4. **`Templates/case.md`를 복사해 채운다.** frontmatter의 `id`는 slug와 반드시 일치시킨다.
   `status: draft`로 둔다. **frontmatter에 metrics 필드를 만들지 않는다** — 숫자는
   본문 '결과' 섹션에만 적는다.

5. **소스에 없는 수치·기술을 지어내지 않는다.** 확인 안 된 값은 빈칸으로 두고
   사용자에게 묻는다. 이건 협상 대상이 아니다.

6. 작성 후 `python tools/build.py validate`를 실행해 형식 오류가 없는지 확인하고,
   `python tools/build.py index`로 `Cases/INDEX.md`를 갱신한다.

7. 다 쓴 뒤 사용자에게 알린다: 이 사례는 `draft` 상태이며, `/review-case <id>`를
   통과해야 빌드에 쓸 수 있다는 것을 상기시킨다.
